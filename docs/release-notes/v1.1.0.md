# mermaid-tty v1.1.0

More flowchart and sequence syntax draws, layouts are cleaner, and installing no longer shows a config notice.

## Install

```sh
claude plugin marketplace add D0n9X1n/mermaid-tty
claude plugin install mermaid-tty@mermaid-tty --config theme=default
```

Needs Claude Code 2.1.287 or later. Already on v1.0.0? Run `claude plugin update mermaid-tty@mermaid-tty`.

## What's new

- **Install without a notice (#5).** The install line saves the default theme, so Claude Code no longer reports a `userConfig` option as not yet set.
- **More flowchart syntax (#4).** Text-form two-headed links such as `A <-- t --> B`, mixed end marks such as `<--o`, partly quoted labels `["a" b]`, `@{ … }` split over lines, plain Markdown strings and `#…;` character codes now draw. A few forms that Mermaid 12.2.0 itself rejects or reads differently, such as `linkStyle 0 stroke:#f00;`, now show their source instead.
- **More sequence syntax (#4).** `;` between statements, `#` comments, `autonumber` with a start, a step, `off` and restarts, keyword and number participant ids, and `box` titles all draw as Mermaid shows them. Columns follow Mermaid's participant order, which `activate` no longer changes.
- **Cleaner layouts (#8).** In state, class and ER diagrams, a pair of edges between two nodes is drawn side by side, labels on long back edges sit by their turn, and inheritance heads stand a cell apart.
- **Decimal frontmatter values (#7).** A config value such as `0.5` now reads as a number, as in Mermaid.
- **Stricter fallbacks.** An empty `accTitle:` or `accDescr:` falls back, since Mermaid reads the next line as its text. Flowchart `@{ … }` keys and values that YAML would read differently from plain text now fall back as well. So does a flowchart id that Mermaid's lexer reads as a keyword, such as `end-x` or `1style`; ids such as `styleX` and `endpoint` still draw.
- **Steadier tests (#10).** The Windows end-to-end mono check no longer trips on Claude Code's own spinner.

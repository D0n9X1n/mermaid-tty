# mermaid-tty v1 acceptance tests (normative)

This file lists the acceptance checks for spec A ([`…-design.md`](2026-10-27-mermaid-tty-v1-design.md)) and spec B ([`…-docs-release.md`](2026-10-27-mermaid-tty-v1-docs-release.md)). Spec C's per-type checks are in [`…-diagram-matrix.md`](2026-10-27-mermaid-tty-v1-diagram-matrix.md).

Every row is a must-pass check that CI runs: `.github/workflows/ci.yml`, on Linux, macOS and Windows, for every push and pull request, mostly through `scripts/check.sh`. Parts marked otherwise:
- ***release***: runs in `release.yml` on a `v*` tag;
- ***review***: a judgment recorded in `docs/reviews/`. CI still runs its objective parts, and fails when a reviewed file no longer matches the content hash its verdict records.

## Spec A

| ID | Requirement | Check |
|---|---|---|
| A1 | Flowchart syntax | There is one fixture per feature in requirement 1: each shape, edge kind, edge end and label form; chains; `&`; nested subgraphs with `direction`; comments; the frontmatter title; and the ignored directives. Each fixture renders and validates at 60, 80 and 120 columns and matches its golden snapshot. |
| A2 | Sequence syntax | There is one fixture per feature in requirement 2. Each is checked the same way as in A1. |
| A3 | Flat nodes | For every shape: a one-line label renders as exactly 1 row; a `<br/>` label with N lines renders as N rows; a wrapped label takes as many rows as it has wrapped lines. No row of a node consists only of border glyphs. Under the mono theme, which has no color, every pair of shapes has different end caps. |
| A4 | Width | **`width()` table test:** ASCII counts 1; `中`, `ア` and `한` count 2; `─`, `│`, `┌`, `◇` and `▶` count 1; `e`+U+0301 counts 1; ZWSP counts 0. Text containing ZWJ, VS15/VS16, regional indicators, emoji modifiers or control characters is unsupported, and the diagram falls back. **Fit ladder:** each step (tighter gaps, wrapped labels, LR→TD) has a fixture sized so that this step is the first one that fits, and the test asserts which step was taken. A width below the minimum falls back. |
| A5 | Fail closed | **Mutation tests:** the validator receives a hand-broken layout for each invariant, and each must fail. The broken layouts are: a missing label instance, a duplicated label instance, a disconnected edge end, an overwritten glyph, and an overlong row. Distinct nodes with identical text pass, because instances are counted by node id. **Errors:** parse errors and unsupported types return `null`, and the hook then draws the original fence. The reason is logged only at debug level; the test asserts that nothing extra appears in the drawn tree. |
| A6 | Source preserved | **Hook tests:** cover prose, then a diagram, then prose; two adjacent fences; a fence between two paragraphs; and a reply with CRLF line endings. The prose reaches `next()` unchanged and the diagrams render in order. An unclosed fence is passed to `next(e)` untouched, and so is any reply on a non-terminal surface. **In Claude Code:** see A9. |
| A7 | Colors | Unit tests assert the color of each of the 7 roles under the default mapping (theme keys) and under each of the 5 palettes. A hook test asserts that the drawn spans carry those colors. |
| A8 | Zero install | **Portability** (`scripts/check-portable.ts`): `package.json` has no `dependencies`. Every import under `core/` and `hooks/` is relative, except type-only `claude-code` imports. The code uses none of: `node:` imports, `require`, `process`, `Buffer`, `document`, `window`, `eval`, `new Function`, or dynamic `import()`. **Benchmark** (`scripts/bench.ts`): renders each corpus or fixture diagram 20 times, cold, at 80 columns, and reports p50 and p90 together with the machine and Node version. p90 must be 50 ms or less on the development Mac; in CI, on each OS, it fails above 200 ms, which catches algorithmic regressions without timing flakes. **Cache:** an LRU of 64 entries, keyed by (text, width, theme). Tests cover a hit; a miss whenever any part of the key changes; and eviction of the least recently used entry when a 65th is added. **No build:** in a fresh `git clone` of the commit, with no `npm install` and no build step, `node --test`, `claude plugin test .` and `scripts/smoke.ts` all pass. `scripts/smoke.ts` renders a flowchart fixture through `core/render.ts` from the checked-in sources. **Validation:** `claude plugin validate .` passes. **Platforms:** CI runs `scripts/check.sh` on Linux, macOS and Windows. `.gitattributes` keeps text files LF, so goldens compare byte for byte. Every glyph the renderer emits, outside source text, comes from one allow-list in `core/glyphs.ts`: printable ASCII plus the glyphs the matrix names. No non-ASCII glyph in it has the Unicode `Emoji` property (so `►`/`◄`, never `▶`/`◀`, which some terminals draw as wide emoji); a test scans every golden. |
| A9 | End to end | **`scripts/e2e/`, a separate CI job on all three OSes:** real Claude Code (the pinned version; the weekly run uses the latest) loads the repo with `--plugin-dir`, in a fresh config, against a mock Messages API (`ANTHROPIC_BASE_URL`; no account or secret), driven through a pseudo-terminal at 100 columns. The mock replies with prose, a CJK flowchart, a sequence diagram, an unsupported diagram and an unclosed fence. Reading the reconstructed screen and its colors, the test asserts: each diagram is drawn as themed truecolor rows; the prose is intact; the unsupported and unclosed fences show their source; and after ctrl+o the original Mermaid source is shown. It runs once with the default mapping and once per curated theme through `userConfig`. ***release*:** `release.yml` repeats it on the copy installed from the marketplace. |
| A10 | Corpus | `fixtures/corpus/` holds at least 90 synthetic blocks with the owner's feature mix: mostly flowchart and graph, plus sequence, with quoted labels, edge labels, CJK, `<br/>`, subgraphs and frontmatter. Every block renders and validates at 80 and 120 columns. On the development Mac the same test also takes a path to the owner's 87 private blocks, which are never committed. |

## Visual review (*review*, for A and C)

**Gallery:** every golden, rendered to PNG at 80 columns, at 60 columns, and with CJK labels.

**In CI:** `scripts/render-gallery.ts` renders the gallery as SVG and uploads it as a build artifact. `scripts/check-tangle.ts` checks the four tangle rules below on every golden's role map. Each curated palette's role colors have a contrast ratio of at least 3:1 against its background, and differ pairwise by at least 0.08 in OKLab; mono is exempt from the color checks, because it tells roles apart by glyphs and caps.

**Reviewers:** the PM inspects the PNGs. A cross-family reviewer inspects the text and the role map.

**A diagram is tangled if any of these is true:**
- an edge passes through a node;
- two edges share a segment but share no endpoint;
- an edge's direction is ambiguous, because its arrowhead is missing or sits on a junction;
- an edge label is not adjacent to its edge.

**A diagram passes when** every label is readable, it is not tangled, and its colors tell the roles apart.

## Spec B

| ID | Requirement | Check |
|---|---|---|
| B1 | README | **`scripts/check-docs.ts` asserts:** the hero has the logo image and tagline; the CI, release, license and stars badges are present; the exact two-line install block is present; the Before/after, Themes, Configuration and FAQ sections exist, with the FAQ covering fallback, width and CJK; the wiki links (English and 简体中文) are present; every `assets/` image exists and matches a fresh `render-svg` run; in each SVG, every glyph's `x` equals its column × cell width. **Beauty (*review*):** the PM reviews the rendered GitHub page. |
| B2 | Wiki pages | All five named pairs exist. Each pair has the same heading levels in the same order. Each page opens with exactly one link to its twin, which is the only cross-language link. zh-CN bodies contain CJK prose; English bodies contain none outside code. **Per paragraph:** every non-code paragraph of a zh-CN page contains CJK characters, so a mostly untranslated page fails. **Translation (*review*):** the PM and a cross-family reviewer confirm that each of the five pairs says the same things in full, and record the verdict in `docs/reviews/`. |
| B3 | Publishing | **`scripts/test-wiki-publish.sh`**, run in throwaway repos, covers: mirroring, a no-op run, and removal of stale pages. **`check-docs.ts`** asserts the workflow's triggers (`push` to `main` and `workflow_dispatch`), the job-scoped `contents: write` permission, and SHA-pinned actions. ***release*:** the workflow run on `main` succeeds and the wiki shows the pages. If the wiki repo doesn't exist yet, the one-click bootstrap is reported to the owner and the run is repeated. |
| B4 | CI | `check-docs.ts` asserts that `ci.yml`: runs on push and pull_request; runs a matrix of ubuntu-latest, macos-latest and windows-latest; pins actions by SHA; sets up Node 24 and Claude Code; runs `scripts/check.sh` and the A9 end-to-end job; and has a weekly scheduled run with the latest Claude Code. It also asserts `release.yml`'s `v*` trigger and SHA pins. The PR's CI run is green on all three. |
| B5 | Release | **Every PR:** CI installs the plugin from the local marketplace (`claude plugin marketplace add ./`), which catches `marketplace.json` mistakes before release. ***release*:** on the `v1.0.0` tag, `release.yml` checks that the tag matches `plugin.json`'s version and that the release notes contain both install commands, installs the plugin from the GitHub marketplace into a fresh config, and runs A9 against the installed copy. |
| B6 | Icon | `scripts/make-icon.sh` produces `.claude-plugin/icon.png` from `assets/icon.svg`. The PNG is 512×512, read from its header (`sips` confirms on the Mac), and under 2 MB. |
| B7 | CI coverage | `ci/coverage.json` maps every row ID in this file (A1–A10, B1–B7) and the visual-review checks to CI steps. `scripts/check-ci-coverage.ts`, run by `check.sh`, fails if a row has no step, a mapped step is missing from `ci.yml` or `release.yml`, or a step names an unknown row. |
